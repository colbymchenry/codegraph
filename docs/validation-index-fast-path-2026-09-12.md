Индекс хранит `indexed_at_commit`. Проверка объединяет рабочие изменения
Git с diff между сохранённым коммитом и HEAD и хеширует только кандидатов.
Если отметка отсутствует или недоступна, используется полный inventory.
Полный sync обновляет отметку; частичный sync её сохраняет.
Сам filesystem reconcile внутри sync сохраняется.

## Дополнения к #1848

- HEAD для полной индексации фиксируется до начала работы, чтобы коммит во
  время индексации не считался автоматически обработанным.
- Ошибка committed diff переводит проверку на полный inventory.
- NUL-разделители committed diff сохраняют имена с кириллицей и табуляцией.
- Удалённый коммитом, но восстановленный на диске файл проверяется по
  текущему содержимому; его символы не удаляются из-за устаревшего статуса D.
- Fallback сохраняет проверку существования файла для unstaged удаления.

Исправления extraction/store и CLI guard из предыдущей сборки сохранены.

## Локальное сравнение скорости

Синтетический Git-репозиторий: 2000 TypeScript-файлов, около 8.87 MB.
Два прогрева, 10 измерений каждого варианта, порядок чередуется.
Сравнивались метод из `086e577b` и новая сборка; одинаковые записи хешей
в памяти, без SQLite и без построения графа. Каждый набор изменений
проверялся assertion. В таблице верхняя медиана десяти измерений.

| Чистое | 57.60 | 19.88 |
| Незакоммиченная правка | 56.64 | 20.09 |
| Та же правка после commit | 57.32 | 24.24 |

Это тёплый in-process microbenchmark, не end-to-end CLI и не реальный
крупный проект. Результаты и скрипт: `.scratch/freshness-benchmark.json`
и `.scratch/freshness-bench.cjs` (локальные, исключены из VCS).

Ограничение подхода upstream: изменения, скрытые через `assume-unchanged`,
могут отсутствовать в Git-кандидатах; полного сканирования на каждом status
больше нет. Для полного обновления остаётся полная индексация.
