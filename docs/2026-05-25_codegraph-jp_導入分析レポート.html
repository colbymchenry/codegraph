1. 対象ツールの分析

2026-05-25 analysis codegraph tool

概要

CodeGraph は、ローカルで tree-sitter によりソースを AST 解析し、シンボル・呼び出し関係・インポート・フレームワークルートを SQLite ナレッジグラフ（.codegraph/codegraph.db）に格納するコードインテリジェンス基盤です。Claude Code / Cursor / Codex CLI / opencode / Hermes Agent 向けに MCP サーバー（codegraph serve --mcp）として公開され、エージェントは grep/Read の反復探索の代わりにグラフ照会で構造質問に答えます。

本リポジトリは colbymchenry/codegraph の fork（説明文: 「コードの地図化」）で、パッケージ名は現状 @colbymchenry/codegraph のままです。日本語化（codegraph-jp）は本レポート §3 の設計対象として扱います。

Cursor 固有の実装要点

Cursor は MCP 子プロセスの cwd がワークスペース根でない かつ initialize で rootUri を送らないため、process.cwd() だけでは .codegraph/ を見つけられません。その対策としてインストーラは args に --path を付与します。

  • global インストール: --path ${workspaceFolder}（Cursor が展開）
  • local インストール: インストール時の絶対パス
  • rules: .cursor/rules/codegraph.mdc（alwaysApply: true）— ネイティブ grep より codegraph を優先させる指示。global では mcp.json のみ、rules は codegraph init でプロジェクトに生成

技術スタック・制約

  • ランタイム: Node 20–24（25+ は WASM OOM のためハードブロック、CODEGRAPH_ALLOW_UNSAFE_NODE で上書き可）
  • DB: node:sqlite + WAL（ネットワークドライブではロック問題の可能性）
  • 配布: バンドル Node 付きバイナリ + npm シム、.gitignore 尊重、1MB 超ファイルスキップ
  • テスト: Vitest、36 ファイル・800+ ケース（本環境 Windows で 5 件タイムアウト — §3 参照）

2. 導入後の効果予測（Cursor 連携想定）

2026-05-25 analysis cursor

前提（マスター環境）

  • Cursor を主エディタとし、プロジェクトごとに .cursor/rules/ および MCP（mcp.json）を運用
  • 対象リポジトリはマルウェア解析・汎用ツール制作など 中〜大規模（Python/TS/C 混在）が多い
  • エージェントは構造探索（呼び出し関係・影響範囲）と実装の両方を行う

定量効果（上流ベンチマークの外挿）

公式ベンチ（Claude Opus 4.7 headless、v0.9.4）では、CodeGraph 有効時の中央値で コスト約 35% 減・トークン約 57% 減・時間約 46% 短縮・ツール呼び出し約 71% 減。大規模 TS（VS Code）ではファイル Read ゼロで回答するケースが報告されています。

マスター側のリポジトリ規模感期待される効果根拠
大（数千ファイル、複数言語）高 — 探索ターン大幅削減VS Code / Django ベンチに近い
中（数百〜千ファイル）中〜高Excalidraw / Tokio 級
小（<200 ファイル）低〜中Gin 級 — ネイティブ grep でも十分な場合あり

Cursor 特有の定性効果

  1. コンテキストウィンドウの節約: codegraph_explore が複数ファイルを 1 MCP 呼び出しにまとめるため、連続 Read よりトークン効率が良い。
  2. ルール連携: codegraph.mdc が常時適用されると、Agent が「grep 先行」を避け、既存の .cursor/rules/*.mdc（解析 OPSEC 等）と併用しやすい。
  3. マルウェア解析ワークフロー: デコンパイル C は CodeGraph 対象外だが、解析ツール本体（Python/TS） の改修・YARA 生成パイプライン理解では call graph / impact が有効。検体バイナリはインデックスしない運用と両立。
  4. オフライン・機密: 100% ローカル SQLite のため、顧客案件コードをクラウドに送らない方針と整合（§90-security-ethics と一致）。

導入時の推奨手順（Cursor）

# 1. インストール（Windows）
irm https://raw.githubusercontent.com/matrix9neonebuchadnezzar2199-sketch/codegraph/main/install.ps1 | iex
# または: npm i -g @colbymchenry/codegraph

# 2. Cursor 向け設定
codegraph install --target=cursor --location=global --yes

# 3. 各プロジェクト
cd F:\Cursor\your-tool
codegraph init -i   # インデックス + .cursor/rules/codegraph.mdc

# 4. Cursor を再起動（MCP 読み込み）

リスク・効果を下げる要因

  • 初回インデックス: 大リポジトリでは数分〜十数分。完了前は MCP が「not initialized」。
  • rules 未配置: global のみで init -i していないプロジェクトでは、エージェントが CodeGraph を使わずオーバーヘッドのみ、という README 上の注意と一致。
  • 動的言語・メタプログラミング: 解決できない呼び出しは trace で「動的ディスパッチ」注記 — 完全自動フロー追跡ではない。
  • WSL / ネットワークドライブ: WAL 無効時は database is locked の可能性（README 記載）。

総合予測

マスターの Cursor 運用（複数ツールリポジトリ・横断ルール・長時間 Agent セッション）では、構造理解・影響調査フェーズで 30〜50% 程度のトークン/ツールコール削減が現実的な見込み。字面検索・設定ファイル・ドキュメント編集のみのタスクでは効果は限定的。日本語化後はインストーラと MCP 説明文が読みやすくなり、導入率（init 実行・rules 維持）が上がる副次効果が見込める。

既知のバグ・エラーリスク

  • Cursor cwd 問題: --path 未設定の手動 mcp.json では常に「not initialized」— インストーラ経由必須。
  • Node 25 / 古い Node: 起動時に明示バナーで exit（意図的）。
  • 巨大ファイル・生成物: .gitignore 外の committed vendor/dist はインデックスされる — 運用で .gitignore 管理。
  • MCP ツール説明の英語長文: Cursor のツール選択にそのまま載る — 日本語化でトークン削減の副効果は小さいが、人間可読性は向上。
  • Windows CI ギャップ: mcp-roots タイムアウトは CI 未整備時に regression を見逃す可能性。

完全日本語化 — 設計方針

「完全日本語化」は ユーザー向け文字列の 100% ロケール化 を指し、シンボル名・ファイルパス・抽出されたソースコードは翻訳対象外とする。

Cursor + 既存ルールとの統合案

マスターの F:\Cursor\.cursor\rules/ に、CodeGraph 利用時と解析データ貼り付け時の境界を 1 本の codegraph-opsec.mdc で明示することを推奨する（例: デコンパイル C は CodeGraph に載せない、IoC は defang opt-in）。CodeGraph 本体ではなく ワークスペースルール で実装する方が、upstream マージと両立しやすい。
