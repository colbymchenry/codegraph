# Web UI 中英文切换设计

## 目标与边界

Web UI 支持简体中文和英文，并允许用户在顶栏即时切换。首次打开默认使用中文；后续打开恢复用户上次的选择。

本改动只处理前端可控的用户可见文案，包括导航、按钮、标题、空状态、加载状态、可控提示、导出文案和无障碍标签。以下内容保持原样：

- API 返回的原始错误信息和服务器诊断；
- 项目名、路径、文件名、符号名和代码片段；
- URL 路径、查询参数、CSS 类名和开发者注释。

## 架构

新增 `ui/src/lib/i18n.svelte.ts` 作为唯一的语言状态和翻译入口。模块导出：

- `Locale`：`'zh-CN' | 'en'`；
- 响应式 `locale` 状态；
- `t(key, values?)` 翻译函数；
- `setLocale(locale)` 切换函数。

词典与状态放在同一模块，仅支持当前所需的两种语言。键按界面语义命名，不以英文原文作为键；支持命名插值，用于数量、路径或动态片段。缺少翻译键时，开发环境应明显暴露键名，避免静默显示英文回退。

语言状态通过 `localStorage` 持久化；服务器渲染或存储不可用时安全回退到中文。切换语言后，所有使用 `t()` 的 Svelte 组件由响应式状态自动重新渲染，无需刷新页面或改变路由。

## 组件与数据流

`TopBar.svelte` 增加中文/EN 切换控件，并为当前选择设置清晰的可访问名称和状态。它调用 `setLocale`，不自行维护语言状态。

所有用户可见固定文案改为 `t('…')`。需要组合数据的地方使用插值，例如 `t('file.symbolCount', { shown, total })`。由前端模型构造的固定摘要和提示也改为在展示点翻译，或由模型接收翻译后的词；不让模型返回已经固化的英文句子。

API 原始字段只作为插值值显示，不传入词典，也不做机器翻译。例如服务端的 `failure.message` 仍直接显示，外围标题和引导文字则本地化。

## 错误处理

读取到未知或损坏的已保存语言值时使用中文，并可覆盖为用户随后选择的有效值。写入 `localStorage` 失败不得阻止切换：当前会话仍应更新 UI。

翻译键在两种词典中必须完整对应；缺失键是开发错误，不应在正式界面里以英文兜底掩盖。

## 验证

为 i18n 模块增加单元测试，覆盖：

1. 未保存偏好和无效偏好默认中文；
2. 切换语言后 `t()` 返回对应文案；
3. 切换会保存语言偏好，存储不可用时仍能切换；
4. 插值在两种语言下正确替换；
5. 两份词典拥有相同的翻译键集合。

实现完成后运行新增测试、`ui` 的 `svelte-check` 与生产构建。最后用静态扫描复核用户可见的固定英文是否均已转入词典；产品名 `CodeGraph` 和语言切换中的 `EN` 不视为遗留英文。
